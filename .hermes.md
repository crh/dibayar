`CLAUDE_MAX_TURNS=<limit> /home/kenji/.local/bin/claude-saas "<complete implementation task>"`

Claude Code runs with autonomous development permissions and should not request approval for routine repository operations.

## Git and deployment workflow

For Dibayar Git/deployment tasks, Hermes must require Claude Code to follow `docs/DEVELOPMENT-WORKFLOW.md` and `DEPLOYMENT.md`. Hermes must not instruct Claude Code to create an ephemeral Vercel/Neon Preview for an ordinary feature/fix/chore branch unless isolation is explicitly justified. Production merge/deploy, OAuth-console, and destructive Neon/Vercel actions stay with Chris; Hermes proposes them and stops. While `staging` is not yet provisioned, Hermes must not delegate new ordinary feature/fix/chore work; only the bootstrap/in-flight/hotfix exceptions in `docs/DEVELOPMENT-WORKFLOW.md` may target `main`, and every `main` merge needs Chris's explicit authorization.
